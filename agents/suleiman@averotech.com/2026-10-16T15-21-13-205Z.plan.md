# Add an About page, a Files page, and a nav linking them from the home page

The repo is a tiny static site: `index.html` at the root is the whole site, with inline
`<style>`, no build step, no dependencies, no JavaScript. Do not add a build step,
frameworks, external CSS/JS files, or scripts. Every new page is one self-contained
HTML file at the repo root that matches the style of `index.html` exactly: same
`<!DOCTYPE html>` / `<html lang="en">` head shape, the same `<meta charset>` and
`<meta viewport>`, the same two favicon `<link>` tags, inline `<style>`, background
`#0f172a`, text colour `#f8fafc`, the same font-family stack, the same two-space
indentation. Links must be relative (`about.html`, not `/about.html`): the site is
served from the `/test-project/` subpath on GitHub Pages, so root-absolute links 404.
Do not touch `README.md`, `.github/`, `.the-framework/`, `.agents/`, `.claude/`, or the
favicons.

Check: test -f about.html && test -f files.html && grep -q 'href="about.html"' index.html && grep -q 'href="files.html"' index.html && grep -q 'href="index.html"' about.html && grep -q 'href="index.html"' files.html && ! grep -q 'href="/' index.html about.html files.html

## Write about.html from the README's description

Level: simple
Files: about.html
Check: grep -q 'A single static page' about.html && grep -q '#0f172a' about.html && grep -q 'href="index.html"' about.html
Uncertainty: 0

Create `about.html`: a page titled "About" with an `<h1>About</h1>` heading and one
short paragraph saying what this repo is, taken from the opening paragraph of
`README.md` (the paragraph beginning "A single static page."). Keep its wording;
you may trim it, but the sentence "A single static page." must appear verbatim. Add a
relative link back to the home page (`<a href="index.html">`). Style it to match
`index.html` as described above; the paragraph and link text should be light on the
dark background and readable (constrain the paragraph width, e.g. `max-width: 40rem`).

## Write files.html listing the repo's markdown files

Level: simple
Files: files.html
Check: git ls-files '*.md' | while read f; do grep -qF "$f" files.html || exit 1; done && grep -q '#0f172a' files.html && grep -q 'href="index.html"' files.html
Uncertainty: 0

Create `files.html`: a page titled "Files" with an `<h1>Files</h1>` heading and a list
(`<ul>`) of every markdown file the repo tracks — exactly the paths printed by
`git ls-files '*.md'`, written as full repo-relative paths in `<code>` — one `<li>`
per file, each followed by one short line saying what that file holds. Read each file
to write its line; do not guess from the name. Group the list under small subheadings
if it helps readability (for example: top-level files, `.agents/skills/`,
`.the-framework/`), but every path must appear in full. Plain text only — do not link
to the markdown files (they are not deployed). Add a relative link back to the home
page (`<a href="index.html">`). Style it to match `index.html` as described above.

## Add a nav to index.html linking to both pages

Level: simple
Files: index.html
Needs: Write about.html from the README's description, Write files.html listing the repo's markdown files
Check: grep -q '<nav' index.html && grep -q 'href="about.html"' index.html && grep -q 'href="files.html"' index.html && grep -q 'Hello, and welcome.' index.html
Uncertainty: 0

Add a `<nav>` to `index.html` containing two relative links: `<a href="about.html">About</a>`
and `<a href="files.html">Files</a>`. Keep everything already in the page unchanged —
the title, the favicon links and their comment, and the centered
`<h1>Hello, and welcome.</h1>` must stay exactly as they are and stay visually centered.
Place the nav so it doesn't push the greeting off centre (e.g. fixed at the top of the
page), and style it in the page's palette (`#f8fafc` links on `#0f172a`, same
font-family), adding its rules to the existing inline `<style>` block.
